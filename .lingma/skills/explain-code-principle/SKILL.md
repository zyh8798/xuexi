# 代码原理讲解助手

当用户说「不理解」「想不通」「看不懂」「解释一下」时，读取本 skill，按以下方式讲解。

## 讲解格式

用**用户视角**、**执行流程**的方式拆解，而不是堆砌概念：

1. **先用我的话来解释**：用大白话概括这段代码在干什么
2. **关键就是**：点出最容易被忽略的核心点（如 Map 用对象当键）
3. **执行流程**：按调用顺序一步步走，说明每一步的判断和结果
4. **问题就在于**：如果用户卡住了，指出常见踩坑（如 console.log 打印幻觉）

## 常见易踩坑点（讲解时主动提及）

### 1. Map 可以用对象当键

很多人不知道：`Map` 的 key 可以是**对象引用**，而普通对象的 key 只能是字符串。

```javascript
const map = new Map()
const obj = { a: 1 }
map.set(obj, '我是值')  // obj 作为键，不是 "obj" 字符串
map.has(obj)           // true，按引用比较
map.get(obj)           // '我是值'
```

**关键**：深拷贝里用 `map.set(原对象, 新对象)`，下次遇到同一个对象引用时，`map.has(obj)` 能识别出来，直接返回已拷贝的新对象，避免无限递归。

### 2. console.log 的对象打印幻觉

`console.log(obj)` 打印对象时，浏览器显示的是**展开时的快照**，不是执行那一刻的值。

```javascript
const obj = { a: 1 }
console.log(obj)  // 点开看时，可能已经变成 { a: 1, b: 2 }
obj.b = 2
```

**建议**：需要看某一刻的值时，用 `JSON.stringify(obj)` 或 `console.log(JSON.stringify(obj))`。

### 3. 递归里的「袋子」思维

递归函数如果需要在多次调用间共享状态（如「哪些对象已经拷贝过」），需要一个**在递归之外的变量**——就像袋子，每次递归都往里放、往外查，而不是每次新建。

- 深拷贝的 `map` 就是这个袋子
- 防抖的 `timer` 也是
- 闭包里的变量也是

## 示例：深拷贝 + 循环引用

**用户问**：这段深拷贝里的 map 是干什么的？

**按本 skill 讲解**：

> 先用我的话说：map 是一个「登记簿」，记录「原对象 → 新对象」的对应关系。
>
> **关键**：Map 能用对象当键，所以 `map.set(obj, res)` 存的是「这个 obj 引用 → 它的拷贝 res」。下次递归遇到 `obj.self` 指向同一个 obj 时，`map.has(obj)` 为 true，直接 `return map.get(obj)`，不再递归，避免死循环。
>
> **执行流程**：
> 1. 第一次调用 `myDeepClone(obj)`，obj 是 `{ a: 1, self: obj }`
> 2. 创建空对象 res，`map.set(obj, res)`
> 3. 遍历到 `a`：1 是基本类型，直接返回
> 4. 遍历到 `self`：值是 obj 自己，`map.has(obj)` 为 true，返回 `map.get(obj)` 即 res，不继续递归
> 5. 最终 `obj2.self === obj2`，正确
>
> **问题就在于**：如果不理解「对象能当 Map 的键」，会想不通 map 怎么「认出」同一个对象；另外 `console.log(map)` 时对象会显示为引用，展开看到的是当前状态，容易产生「打印不对」的错觉，用 `JSON.stringify` 看快照更清晰。
